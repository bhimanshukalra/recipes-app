# Share extension: PoC results and handoff

Branch: `poc/share-extension` (commit `cefbee7`). Stack: Expo SDK 58, React Native 0.88, Expo Router, `expo-share-extension` 5.0.6.

## Question the PoC answered

Can a user share a recipe page from Safari and have the app receive its JSON-LD, including on sites that return 403 to a plain `fetch` (Allrecipes, Serious Eats)?

**Verdict: yes, on the iOS Simulator.** The extension runs inside Safari, so it reads the page the user is already viewing. That is why the 403s do not apply.

## Test results

| Page | JSON-LD | Result |
| --- | --- | --- |
| Allrecipes (pancakes) | 18,224 chars | 7 ingredients, 5 steps |
| Allrecipes (cookies) | 19,158 chars | 11 ingredients, 9 steps, rendered in app via real handoff |
| Serious Eats (chili) | 23,369 chars | 37 ingredients, 8 steps |
| Love & Lemons | 2 blocks (16,150 + 938) | 8 ingredients, 5 steps |
| BBC Good Food | 5 blocks | 6 ingredients, 5 steps |
| example.com | 0 blocks | No crash, shows "no recipe" |

## How it works

1. `preprocessing.js` runs in Safari. It collects every `script[type="application/ld+json"]` and returns `{url, title, jsonld}`. Setting `preprocessingFile` is also what enables web-page sharing and delivers the page content.
2. `index.share.js` registers the `"shareExtension"` component. `src/share-extension/ShareExtension.tsx` is currently a diagnostic screen.
3. `src/share-extension/extract-recipe.ts` finds the Recipe node (handles `@graph`, `@type` arrays, HowToStep and `itemListElement` flattening) and builds a compact recipe.
4. The extension calls `openHostApp("recipe?data=<base64url>")`. `src/app/recipe.tsx` decodes and renders it.

## Gotchas (read before changing anything)

- **Base64url is required for the handoff.** A custom-scheme query value is decoded one time too many natively, so a literal `&` (for example "beef & drain") truncated the payload. `encodeRecipePayload` uses base64url (`[A-Za-z0-9_-]` only). Percent-encoding and decode loops did not fix it.
- **SDK 58 needs local patches.** `plugins/with-share-extension-fixes.js` (listed in `app.json` before `expo-share-extension`, so its mod runs after) does two things:
  - Raises the extension deployment target from 15.1 to 16.4. `ExpoDomWebView` needs 16.4, otherwise the build fails.
  - Patches `ShareExtensionViewController.swift` to use `ExpoReactNativeFactory` (with `internal import Expo`) instead of `RCTReactNativeFactory`. Without it, `globalThis.expo` is missing and the extension fails with `EventEmitter of undefined`, then `"shareExtension" has not been registered`.
  - The plugin throws if the strings it expects are missing, so a library upgrade will fail loudly. Re-check on each `expo-share-extension` bump, or upstream the fixes.
- **Debug builds need Metro running.** The extension fetches its JS from Metro. If Metro stops, the extension is blank.
- **Routing.** `NativeTabs` does not expose unlisted routes, so the app has a root `Stack` with `(tabs)` and `recipe`.
- **`pod install` needs a UTF-8 locale:** `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.
- `expo run:ios` may print an `osascript` System Events error. It is harmless, and the install still succeeds.
- **Simulator limits:** `simctl openurl` shows an "Open in app?" confirm dialog, and the ~120 MB extension memory limit is not enforced.
- **Commit hook** rejects `Co-Authored-By` / Claude attribution lines in commit messages.

## Not verified yet

- Real iPhone run. This needs the Apple Developer account.
- Release build. The extension bundles its JS instead of using Metro.
- Real extension memory behaviour. The largest block tested was 23,369 chars, with no failure in the simulator.
- Android. Plan: `expo-share-intent` with `disableIOS: true`.

## Next steps

1. Replace the diagnostic screen in `ShareExtension.tsx` with real UI, and remove the "No recipe received" debug text in `recipe.tsx`.
2. Clean up extraction:
   - Normalise yield.
   - Format ISO 8601 durations (`PT30M` currently shows raw).
   - Decode HTML entities.
   - Use a real HTML parser.
3. Parse ingredients into structured data (`qty`, `unit`, `name`, `raw`) and store it that way from the start.
4. Persist recipes in the app instead of only passing them through the URL.
5. Run on a real device, then test a release build.
